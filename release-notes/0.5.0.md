# TPS Linter 0.5.0

TPS Linter `0.5.0` is a feature and safety release with one deliberate default behavior change: existing installations receive active-editor Markdown linting after save. It also adds an opt-in frontmatter/body separator rule while keeping automatic filename mutation out of the save path.

## User-visible changes

- Enables **Lint notes on save** by default.
- Debounces repeated active-note modifications for 500 ms and silently applies the enabled Markdown rules.
- Adds default-off **Add blank line after frontmatter**.
- Adds stable note-local rule ID `frontmatter-blank-line`.
- Keeps **Check current note** and **Clean current note** for read-only inspection and explicit content/filename cleanup.
- Keeps every automatic save run content-only; filename cleanup remains manual and TPS Global Context Menu remains the automatic filename owner.

## Safety and correctness

- Uses Obsidian's supported Vault `modify` event and limits queuing to the active source-mode Markdown editor.
- Rechecks the enabled setting, active editor/file identity, Markdown extension, editor/persisted-content agreement, and initial-plus-live exclusions before mutation.
- Skips when the editor has newer unsaved content, while tolerating representation-only BOM and LF/CRLF/CR differences.
- Fresh-reads and runs the complete safety/idempotence pipeline before processing; already-clean and blocked notes receive no `Vault.process` call.
- Recomputes against current content inside `Vault.process` so a stale preflight cannot overwrite a concurrent edit.
- Coalesces event bursts independently per note, retains one delayed rerun for an event received during work, recovers after worker errors, cancels pending work when disabled, and invalidates in-flight work before preventing reruns after unload.
- Resolves current rule settings inside the atomic callback, so a rule disabled while an automatic read is waiting cannot still mutate the note.
- Lets the plugin's own modify event converge through one clean no-write preflight without timing-sensitive event suppression.
- Serializes automatic work with manual same-file cleaning so an edit arriving during a clean is retried.
- Shows no routine Notice and never enters filename planning, collision checks, or rename mutation from the save route.
- Validates frontmatter spacing with strict bounded YAML parsing. Malformed, duplicate-key, non-mapping, directive, anchor, alias, merge-key, or tagged YAML is unchanged.
- Enforces the same 500,000-character frontmatter cap at note-control, safety-inspection, and direct sort boundaries before YAML parsing.
- Preserves BOMs and LF, CRLF, CR, and mixed existing endings; frontmatter-only notes receive no terminal padding.

## Compatibility and migration

- Minimum supported Obsidian version: `1.10.0` (unchanged).
- Persisted settings advance from schema v4 to v5.
- Existing rule choices, H6 behavior, filename behavior, terminal-blank behavior, diagnostics, and intentionally edited exclusions are preserved.
- Existing installations receive `lintOnSave: true` to fulfill the requested enabled workflow.
- Existing installations receive `ensureBlankLineAfterFrontmatter: false`; the new frontmatter-spacing mutation is opt-in.
- No note-data migration is required.

## Known limitations

- Obsidian exposes persisted file modification rather than a public exact Ctrl/Cmd-S event. TPS Linter therefore gates the supported modify event to the active source-mode editor at queue and execution time; a note that remains inactive, has newer unsaved content, or remains in preview mode when execution begins is skipped until a later active save.
- Heading text or level changes can affect explicit fragment links. Disable those rules, use note-local controls, or turn off lint on save where link stability is more important.
- There is no batch clean, inactive-note sweep, paste clean, diff modal, Setext-heading rewrite, list renumbering, or custom regular-expression rule.
- Filename mutation remains blocked while TPS Global Context Menu automatic rename is active or its ownership state cannot be verified.
- Native iOS interaction remains a separate device confirmation.
