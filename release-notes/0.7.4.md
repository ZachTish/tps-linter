# TPS Linter 0.7.4

TPS Linter `0.7.4` narrows automatic linting to deliberate interaction with the active Markdown page. Background Vault modifications no longer schedule cleanup.

## User-visible changes

- **Lint on explicit save or page focus** replaces the prior settings label while preserving the existing `lintOnSave` key, value, default, and settings-sync behavior.
- The conventional Cmd-S shortcut on Apple devices or Ctrl-S elsewhere schedules the active source-mode Markdown editor when the gesture originates inside that page.
- Focus entering the active Markdown page from outside its view schedules the same guarded worker. Returning focus to an Obsidian window also schedules it when that page still owns focus.
- Moving focus between controls inside the same Markdown page does not retrigger linting.
- Background plugin writes, Sync arrivals, metadata updates, autosave persistence, and every other Vault modification no longer schedule TPS Linter.

## Safety and compatibility

- The passive focus and keyboard observers never prevent, replace, or stop Obsidian events. They are installed once per main or popout document, deduplicated across layout restoration, detached when a popout closes, and removed on plugin unload.
- Every automatic request still requires the active source-mode Markdown view, matching document and event target, exact current `TFile`, current enablement, initial-plus-live exclusions, editor/file byte equivalence, current rule settings, and atomic `Vault.process` guards.
- Page-focus no-ops remain silent. Explicit conventional Save keeps its existing bounded no-change, disabled-rule, and safety feedback. Successful mutations keep the existing bounded top-right notice.
- Automatic cleanup remains content-only. Filename cleanup, manual Check/Clean, all cleanup rules, note-local controls, settings persistence, settings sync, defaults, exclusions, schema `7`, and minimum Obsidian `1.10.0` remain unchanged.

## Known limitations

- A user-remapped or menu-based Save is not treated as an explicit trigger. Use the conventional platform chord or move focus from outside the active Markdown page back into it.
- Preview-only, inactive, excluded, deleted, replaced, renamed-away, and newer-unsaved-buffer targets remain fail-closed and unchanged.
- Focus events are intentionally scoped to the active source-mode Markdown view. Settings, modals, sidebars, other views, and internal focus moves do not schedule cleanup.
