# TPS Linter 0.4.0

TPS Linter `0.4.0` is a backward-compatible feature and safety release. It completes the lightweight current-note linter foundation with stable note-local controls, broader protected-Markdown handling, bounded work guards, and hardened filename/content transactions.

## User-visible changes

- Adds `tps-linter: false` and `tps-linter-disabled-rules` top-level frontmatter controls.
- Adds stable rule IDs for filename, whitespace, blank-line, trailing-blank, final-newline, heading, and frontmatter behavior.
- Adds exact HTML-comment and Obsidian-comment body range markers.
- Adds an independent **Clean filenames** switch.
- Adds default-off **Remove trailing blank lines** while preserving exactly one final newline.
- Keeps **Push heading hierarchy down to H6** default-off; a standalone heading reaches H6 and nested outlines retain one-level parent/child steps.
- Lists the note-local syntax and all rule IDs in **Files & safety** settings.
- Reports explicit reasons when ambiguous Markdown or a safety budget prevents cleanup.

## Safety and correctness

- Uses a fresh read and one unconditional `Vault.process` callback for content cleanup.
- Serializes same-file cleans and snapshots rule options for a run.
- Rechecks the union of initial and live exclusions during content and filename phases.
- Re-reads note-local controls, the filename switch, and GCM ownership before rename eligibility.
- Reports Markdown success separately when a later filename rename fails.
- Requires a changed result to preserve note-local controls and be byte-identical on an immediate second pass.
- Preserves BOMs and LF, CRLF, or CR endings.
- Protects frontmatter, fenced and container-relative indented code, math, Obsidian/HTML comments, Templater, raw/delimited/paired HTML, multiline code spans, links, images, wiki links, inline fields, inline math, autolinks, and escaped markup.
- Tracks interleaved list/blockquote containers in source order using CommonMark tab columns and list-padding rules, including partial tabs after quote markers and code-significant list padding above four columns.
- Structurally discovers exact top-level note controls in indented block maps, flow maps, explicit scalar keys, and quoted/escaped keys; nested lookalikes remain ordinary note data, and malformed control-like YAML fails closed.
- Fails closed for unsupported multiline/ambiguous HTML and Markdown link/reference boundaries.
- Bounds note size, total line count, individual line size, container depth, per-line/document protected-token work, frontmatter characters/lines, and sortable field count.
- Cleans Unicode control characters and separator whitespace in filename plans, blocks superscript COM/LPT device names, and compares sibling collisions with Unicode normalization plus case folding.

## Compatibility and migration

- Minimum supported Obsidian version: `1.10.0` (unchanged).
- Persisted settings advance from schema v3 to v4.
- Existing rule choices, H6 behavior, and intentionally edited exclusions are preserved.
- Existing installations receive `cleanFilenames: true` and `removeTrailingBlankLines: false`.
- No note-data migration is required.
- No automatic save/create/modify/file-open hooks, whole-vault mutation command, network access, credentials, or production deployment path were added.

## Known limitations

- Filename mutation remains blocked while TPS Global Context Menu automatic rename is active or its ownership state cannot be verified.
- There is no batch clean, on-save clean, paste clean, diff modal, Setext-heading rewrite, list renumbering, or custom regular-expression rule.
- Advanced YAML layouts that cannot be source-moved and semantically verified are skipped.
- Multiline HTML tags and multiline Markdown link/reference forms are deliberately blocked when the lightweight scanner cannot prove their boundaries.
- Tag-like shortcut/full reference labels fail closed because TPS Linter does not build a document-wide reference-definition index.
- H6 alignment is global across the visible ATX outline; an uneven shallow leaf can remain above H6 to preserve sibling and parent relationships.
- Container-prefixed ATX headings are preserved rather than normalized.
- The read-only Check action may briefly reflect Obsidian's cache; Clean always re-reads and processes the live file.
- Native iOS interaction remains a separate device confirmation.
