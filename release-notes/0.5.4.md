# TPS Linter 0.5.4

TPS Linter `0.5.4` is a backward-compatible performance and reliability release. It makes semantic verification of ordinary string-key frontmatter linear while preserving every released cleanup feature, safety guard, and complex-key comparison path.

## Changes

- String-key Maps now use exact `Map.has`/`Map.get` lookup instead of repeatedly searching and splicing a shrinking entry array.
- Verification still snapshots the right-hand Map before recursive comparison, preserving the released result even if a compared value re-enters and mutates that Map.
- Nested non-string, structural, and mixed-key Maps continue through the released generic comparator because native identity lookup is not equivalent for those supported YAML values.
- Missing keys remain distinct from present `undefined` values, and recursive value comparison is unchanged.
- The implementation adds no persistent cache, settings/data state, fallback route, retry, monkeypatch, polling, or unsupported Obsidian API.

## Objective before/after evidence

- On exact released `0.5.3`, a deterministic 1,000-field reverse-order frontmatter document sorted in 33.62 ms median.
- The final snapshot-preserving implementation sorts the same document in 24.43 ms median, a 27.3% reduction in end-to-end time.
- In the same isolated-comparator run, the frozen released algorithm measured 9.218 ms median and the final linear comparator measured 0.083 ms, a 99.1% reduction.
- The released reverse-order comparator performs 500,500 key comparisons for 1,000 fields. The new path performs linear key scans, snapshot construction, and exact lookups.
- Already-sorted frontmatter still returns before semantic verification, so that no-op path is unchanged.
- These measurements describe the 1,000-field reverse-order fixture and isolated comparator, not a universal whole-plugin speedup.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No command, setting, default, cleanup rule, data field, output contract, work limit, or plugin API is removed or changed.
- No settings or data migration is required.
- The structural comparator is intentionally retained for complex nested YAML keys; it is compatibility logic, not an unreliable fallback.
- `semanticEquals` is exported only from its internal source module as a test seam. It is not attached to the plugin's public `.api`.
- Existing conservative Markdown/YAML limits and documented unsupported syntax remain unchanged.
