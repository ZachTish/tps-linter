# TPS Linter 0.5.2

TPS Linter `0.5.2` is a backward-compatible manual-clean efficiency release. It removes one redundant Markdown cleanup from the ordinary manual **Clean current note** path without changing commands, settings, defaults, cleanup output, mutation guards, filename behavior, or persisted data.

## Changes

- The fresh manual-clean inspection now retains the exact source bytes that produced its verified cleanup result.
- The unconditional atomic `Vault.process` callback reuses that result only when it receives byte-identical content.
- Any concurrent byte change—including BOM or line-ending representation—runs the original cleanup against the current content with the captured manual options.
- Live path exclusions still run before reuse. Filename planning, ownership checks, collision checks, notices, logging, serialization, and rename behavior remain on their existing paths.
- The implementation adds no persistent cache, invalidation system, fallback route, monkeypatch, background work, or unsupported Obsidian API.

## Performance evidence

- The released `0.5.1` path and the optimized path were benchmarked on the same deterministic 35,001-line, 214,780-character dirty note.
- The released two-cleanup simulation measured `125.95 ms` median.
- Exact preflight reuse measured `59.67 ms` median, a `52.6%` reduction in Markdown-engine time.
- Both paths produced equivalent output. Deterministic work-count tests prove one cleanup for unchanged bytes and a fresh second cleanup for every changed revision.

## Validation

- The released `0.5.1` baseline passed 134 unit/property tests and 11 structural/settings contracts before implementation.
- The final versioned `npm test` passed:
  - 135 unit/property tests.
  - 11 structural/settings contracts.
  - TypeScript and the production bundle.
- Regression coverage includes exact object reuse, deterministic full-result equality, one-code-unit changes, BOM changes, LF/CRLF changes, note-control changes, unconditional atomic processing, and live-exclusion ordering.
- Independent adversarial review found no release blocker and confirmed that exact equality is sufficient because the manual path captures one immutable options snapshot.
- A separate final `npm run build` passed and deployed byte-identical artifacts only to `.obsidian/plugins/tps-linter` in the isolated test vault.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. In a synthetic Inbox note, **TPS Linter: Clean current note** cleared one whitespace-only line, capitalized one heading, and adjusted one heading level. A second invocation reported both the filename and Markdown already clean. The note was then moved to `_archive`.
- Test-runtime `data.json` remained unchanged at SHA-256 `0cad907fa12c9c5859b7b4b3df05d8dcb0d0f071b2a195edfb4d02a744679682`.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings, data, or API migration is required.
- All released commands, cleanup rules, note-local controls, safety budgets, exclusions, and filename safeguards remain available.
- Concurrent content never uses the preflight result; it deliberately retains the existing fresh-cleanup path.
- Existing conservative Markdown/YAML limits and documented unsupported syntax remain unchanged.
