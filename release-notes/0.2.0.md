# TPS Linter 0.2.0

TPS Linter `0.2.0` is a backward-compatible feature release that adds TPS-aware Markdown and frontmatter cleanup to the explicit current-note workflow.

## User-visible changes

- Removes consecutive blank lines outside protected YAML, fenced or indented code, math, Obsidian/HTML comments, raw HTML, and Templater regions.
- Adds conservative first-letter heading capitalization by default, with Off and Title Case choices.
- Normalizes ATX heading hierarchy to H1 or H2 and prevents skipped depth increases.
- Sorts safe top-level frontmatter using TPS Global Context Menu's configured property priority when available, then a case-insensitive alphabetical remainder.
- Preserves original key spelling, comments, nested collections, block scalars, quoted values, quoted Templater expressions, and line-ending style.
- Reports and skips unsafe frontmatter instead of guessing, while allowing independent safe body rules to continue.
- Reorganizes settings into four task-oriented, accessible, mobile-responsive destinations without persisting navigation state.
- Adds `_templates` and `System/Templates` to the protected editable defaults.

## Compatibility and migration

- Minimum supported Obsidian version: `1.10.0` (unchanged).
- Persisted settings advance from schema v1 to v2.
- Existing rule choices and custom exclusions are preserved. The v1 migration appends `_templates` and `System/Templates`; intentional removals remain preserved after the first v2 save.
- The new blank-line, first-letter heading, H1 hierarchy, and frontmatter-order rules are enabled by default, but run only when Check or Clean is explicitly invoked.
- No note-data migration is required.
- TPS Global Context Menu remains the automatic filename owner. Its live property list supplies frontmatter priority order without invoking its mutating frontmatter service.
- No automatic save/create/modify/file-open mutation hooks or whole-vault cleanup commands were added.
- The bundled YAML parser is `yaml` `2.9.0` under its ISC license.

## Safety and known limitations

- Heading text and hierarchy rules apply only during an explicit Clean action because changing headings can affect fragment links and TPS heading consumers.
- Setext heading text and semantic or markup-bearing ATX heading text (including TPS fields, math, tags, URLs, and links) are not capitalized.
- Frontmatter sorting skips invalid YAML, duplicate or case-colliding keys, non-map roots, complex keys, directives/document markers, anchors, aliases, merge keys, explicit tags, and source layouts that cannot be semantically verified.
- There is no batch clean, background clean, visual diff, or custom regular-expression rule.
- Native iOS interaction remains a separate device confirmation.
