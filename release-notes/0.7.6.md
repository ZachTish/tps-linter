# TPS Linter 0.7.6

TPS Linter `0.7.6` extends the shared TPS template boundary to automatic linting. When the loaded TPS Global Context Menu exposes its additive version-1 template mutation capability, Save/page-focus linting leaves protected template sources byte-identical.

## User-visible changes

- Templates identified by GCM are skipped by automatic Cmd-S/Ctrl-S and page-focus linting even when they live outside TPS Linter's conventional template-folder exclusions.
- TPS Linter checks the exact note on automatic-worker entry and again immediately before its atomic `Vault.process` mutation.
- **Check current note** remains read-only and **Clean current note** remains an explicit user-authorized cleanup, including for a template.
- There is no new setting, template marker, copied identity rule, scan, migration, or hidden per-note state.

## Compatibility and safety

- Integration uses GCM's additive `api.templates` version-1 method `canAutomaticallyMutate(file)`; it does not read GCM template settings or reproduce tag/property/folder matching.
- A compatible capability must settle to the literal boolean `true`. `false`, a thrown or rejected call, and a non-boolean result all fail closed without entering the automatic mutation.
- Missing GCM, GCM without the additive method, and incompatible API versions retain the released automatic-lint behavior.
- Existing lifecycle, active-editor, exact-file, editor-revision, exclusion, current-settings, content-only, and atomic-process guards remain in force.
- Persisted schema `7`, every setting/default/rule/exclusion/command, minimum Obsidian `1.10.0`, and manual filename ownership are unchanged.

## Validation

- Complete unit/property suite: 273/273 passed. Its focused GCM compatibility subset passes 6/6 and covers literal allow/deny results, exact-file forwarding, method receiver binding, thrown/rejected/malformed failure, and missing/older capability compatibility.
- Structural/settings contracts: 18/18 passed. They require both automatic boundary checks to settle before `Vault.process` and require manual Clean to remain outside the background template gate.
- TypeScript passed with `npx tsc -noEmit -skipLibCheck`.
- The complete declared suite and mandatory separate production-mode build passed and deployed only to the isolated test runtime. Obsidian 1.13.7 loaded Linter 0.7.6 beside GCM 1.50.0; Cmd-S on a deliberately noncanonical Inbox note carrying `tags: [template, keep]` left its SHA-256 byte-identical. The fixture was moved directly to `_archive`.
- Production was not accessed, deployed, or reloaded. This release is ready for a BRAT pull after publication.

## Known limitations

- Automatic template protection requires GCM to be loaded with the additive capability. Older or absent GCM builds intentionally retain TPS Linter's prior behavior for backward compatibility.
- Explicit manual Clean can change a protected template because that action remains direct user authorization.
