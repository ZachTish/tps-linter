# TPS Linter 0.5.6

TPS Linter `0.5.6` is a backward-compatible performance and reliability release. Manual Check/Clean inspection now performs one initial Markdown safety and note-control analysis for the exact file revision and shares it with cleanup, instead of repeating both steps. Every released command, rule, setting, safety guard, and mutation contract remains unchanged.

## Changes

- Adds one pure combined-analysis boundary for a revision's lint controls and Markdown cleanup result.
- Uses that boundary only where manual inspection previously performed the same safety and control analysis twice.
- Keeps public `cleanMarkdown` behavior unchanged for save linting and changed process revisions.
- Keeps a fresh final content read and note-control analysis before any manual filename change.
- Keeps independent post-output note-control comparison and second-pass idempotence verification.
- Adds no persistent cache, settings/data state, fallback route, retry, monkeypatch, polling, or unsupported Obsidian API.

## Objective before/after evidence

- The deterministic manual-inspection seam performs two initial safety scans and note-control parses in exact released `0.5.5` and one of each in `0.5.6`.
- On a synthetic 1,128,890-byte ordinary note, exact `0.5.5` manual composition measured 56.297 ms median and `0.5.6` measured 51.999 ms across 21 interleaved rounds, a 7.6% reduction.
- On an equivalent control-bearing note, the medians were 61.950 ms and 55.853 ms, a 9.8% reduction.
- On a 17,031-byte note disabled by one of 1,000 frontmatter fields, the medians were 12.408 ms and 6.173 ms across 101 interleaved rounds, a 50.2% reduction.
- Independent adversarial measurement reproduced a 7.59% reduction on a 508,890-byte ordinary note and a 49.9% reduction on the 1,000-field disabled fixture.
- Public `cleanMarkdown`, which owns save-lint analysis, remained within interleaved timing noise and produced exactly released output. These measurements cover the synthetic pure-function manual-analysis seam, not universal whole-plugin, Obsidian UI, or save-lint speedups.

  - 140 unit/property tests.
  - 12 structural/settings contracts.
  - TypeScript and its production bundle.

- The hash-pinned 10,003-case corpus produced exact deep equality for released lint-control decisions, combined Markdown results, and public `cleanMarkdown` results across ordinary, dirty, disabled, invalid-control, protected, line-ending, and all three Markdown safety-limit cases.

  - exact-source `Vault.process` reuse remains unchanged;

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No command, setting, default, cleanup rule, data field, output contract, work limit, or plugin API is removed or changed.
- No settings or data migration is required.
- Gains depend on note size and whether note-local controls stop cleanup early.
- Existing conservative Markdown/YAML limits and documented unsupported syntax remain unchanged.
