# TPS Linter 0.5.8

TPS Linter `0.5.8` is a backward-compatible performance and reliability release. Manual filename collision decisions now normalize sibling paths in one ordered pass and stop at the first collision instead of eagerly allocating and then rescanning a second complete sibling array.

## Changes

- Normalizes each sibling path exactly once during collision scanning.
- Preserves the released case-insensitive NFC collision key, normalized collision detail, source-file exclusion, and sibling order.
- Stops the collision-decision scan after the first match while retaining a complete scan when no collision exists.
- Keeps collision scope inside the selected file's parent folder and retains GCM's automatic filename ownership.
- Adds no state, cache, retry, fallback route, monkeypatch, polling, whole-vault scan, or unsupported Obsidian behavior.

## Objective before/after evidence

- Exact public `0.5.7` was pinned at commit `0f76f1eb962ed1562a299f2d2946831a4ccceced`; its `src/cleaner.ts` SHA-256 is `37ecb00b13cec6d2f76adfb1dcd6908a7d6be06625497a99694cd01a1b15833f`.
- The untouched baseline passed 142 unit/property tests, 13 structural/settings contracts, TypeScript, and two production-mode builds with deployment suppressed.
- Baseline `main.js`, `manifest.json`, and `styles.css` matched the public `0.5.7` release byte-for-byte.
- The exact released and candidate `decideFilenameRename` implementations produced zero mismatches across 1,000,000 seeded generated decisions covering every decision reason, early and late collisions, source entries, slash normalization, case differences, and Unicode NFC/NFD forms.
- The complete released and candidate `TPSLinterPlugin.createFilenameDecision` paths produced zero mismatches across another 100,000 seeded cases, including non-file siblings filtered by the real class path.
- Across 31 interleaved rounds with 100,000 sibling files, the complete plugin-class path measured:
  - no collision: 54.961 ms in exact `0.5.7` and 28.430 ms in `0.5.8`, a 48.3% reduction;
  - collision at index 1: 27.320 ms and 2.155 ms, a 92.1% reduction; and
  - collision at index 99,998: 53.948 ms and 28.290 ms, a 47.6% reduction.
- At the pure decision boundary, an observed early-collision call read all 100,000 sibling-path entries in exact `0.5.7` and 2 entries in `0.5.8`, while returning the same collision decision and detail. The complete plugin class still enumerates the parent once to select `TFile` siblings.
- The minified production bundle grows by 24 bytes, from 173,357 to 173,381 bytes.

## Validation

- Focused filename coverage includes no collision, an early normalized collision followed by another equivalent collision, a late case-insensitive collision, source exclusion, repeated/leading/trailing slash normalization, and the existing Unicode NFC/NFD collision.
- A structural contract requires one ordered sibling loop, one normalization call per visited sibling, and explicit early termination.
- The final versioned tree passes 143 unit/property tests and 14 structural/settings contracts.
- TypeScript and the production bundle pass in both the declared suite and the required separate build, with `TPS_NO_DEPLOY=1`.
- The mandatory separate deployment build passed again without suppression and atomically changed only `main.js` and `manifest.json` in the isolated `tps-linter` test runtime; `styles.css` was byte-identical.
- Obsidian 1.12.7 was reloaded in `Obsidian Plugin Test Vault`. Both released Linter commands—**Check current note** and **Clean current note**—were registered after reload. Neither command was invoked, so no note or setting was changed.
- Runtime-owned `data.json` retained SHA-256 `0cad907fa12c9c5859b7b4b3df05d8dcb0d0f071b2a195edfb4d02a744679682` and its original modification time. `.hotreload` likewise retained SHA-256 `7caebdb9e207a5fa31de20194bd27f380a44bcb3e302634f5598823218362556` and its original modification time.
- Production was not accessed or promoted.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No command, setting, default, cleanup rule, data field, output contract, work limit, compatibility behavior, or plugin API is removed or changed.
- No settings or data migration is required.
- The gain applies to manual Check/Clean filename eligibility and grows with the number of sibling files. Filename cleanup remains manual, collision checks remain sibling-file-only, and the parent collection is still enumerated once to preserve file-type filtering and sibling scope.
- Same-named folder collisions remain guarded by Obsidian's supported rename operation, as in `0.5.7`.
