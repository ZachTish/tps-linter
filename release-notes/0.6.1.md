# TPS Linter 0.6.1

TPS Linter `0.6.1` closes the no-op save gap for an already-open Markdown note and adds concise top-right feedback when save lint successfully changes content.

## User-visible changes

- Pressing the conventional platform save chord (Cmd-S on Apple devices and Ctrl-S elsewhere) inside the active source-mode Markdown editor schedules linting even when Obsidian has no changed bytes to persist and therefore emits no Vault `modify` event.
- Persisted edits continue to schedule through Obsidian's supported Vault `modify` event. Shortcut and modify requests coalesce through the existing 500 ms per-note scheduler.
- A native Obsidian notice briefly lists the changes actually applied, including removed blank lines, cleared whitespace-only lines, heading adjustments, frontmatter ordering, and configured spacing additions. It names at most three actions, aggregates the exact remaining fix count, and is capped at 180 characters.
- A failed automatic worker shows a short local failure notice while retaining the structured diagnostic log.
- Already-clean, excluded, inactive, safety-blocked, note-disabled, unsaved-buffer, and plugin-generated convergence passes remain silent.

## Safety and ownership

- The shortcut observer is registered through Obsidian's public component DOM-event API in passive window-capture mode, before Obsidian consumes its own document-level Save handler. It requires exactly the platform-appropriate primary modifier, rejects combined or secondary modifiers, never calls `preventDefault` or `stopPropagation`, and does not replace, invoke, or monkeypatch Obsidian's save command.
- One deduplicated observer covers each current main or popout workspace document. Restored and newly opened popouts are added, closed-popout observers are detached, and the event target must be inside the active source-mode Markdown view rather than Settings, a modal, a sidebar, or another view.
- Startup document discovery tolerates a restored leaf whose container is not attached yet, and unload explicitly detaches and clears every shortcut observer.
- Every shortcut request enters the same active source-mode, exact-file-identity, lifecycle, enablement, exclusion, editor/file-revision, and atomic `Vault.process` guards as a persisted modification.
- Save linting remains content-only. Filename planning and renaming remain manual, and TPS Global Context Menu remains the automatic filename owner.
- The linter's own file modification still requests one convergent rerun. Because no-change results have no notice, one successful automatic cleanup produces exactly one message.
- No file-open, editor-change, startup, inactive-note, batch, paste, create, rename, delete, polling, or whole-vault hook was added.

## Compatibility and migration

- Backward-compatible patch; persisted settings remain schema v6.
- No settings, note, Base, command, rule-ID, API, filename, or stored-data migration is required.
- Minimum supported Obsidian version remains `1.10.0`.
- On touch devices and for ordinary persisted edits, the existing Vault `modify` trigger remains authoritative. A no-op action that emits neither the conventional platform save chord nor a Vault modification cannot be observed through Obsidian's public API.

## Known limitations

- **Remove extra blank lines** collapses two or more eligible body blank lines to one. It intentionally preserves a single separator line.
- Trailing blank padding is controlled by the independent, default-off **Remove trailing blank lines** rule.
- Protected YAML, code, math, HTML, Templater, and note-disabled ranges remain byte-identical.
- Only successfully applied changes receive the routine notice; use manual **Check current note** or optional diagnostics for detailed skip reasons.
- A user-remapped Save command is not observable as the conventional platform chord unless it also persists a modification; TPS Linter does not patch Obsidian's command registry.
