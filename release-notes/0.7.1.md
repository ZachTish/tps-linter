# TPS Linter 0.7.1

TPS Linter `0.7.1` is a safety patch for heading capitalization. It prevents capitalization from changing case-sensitive inline Markdown and link-like text inside ATX headings.

## User-visible changes

- A heading containing a tag, wikilink, embed, Markdown link or image, URL, URI, email marker, inline code span, HTML character reference, escaped Markdown marker, dot-joined domain token, or forward-slash path now keeps its complete text byte-for-byte under both capitalization modes.
- The protection includes punctuation-adjacent, nested, Unicode, and emoji-leading tags; aliases and heading fragments; custom schemes; internationalized domains; IPv4, localhost, relative, and root forward-slash paths; and URL/email autolinks.
- Heading-level normalization remains independent. TPS Linter may correct the number of heading hashes while leaving protected heading text and its capitalization counter unchanged.
- Plain headings without protected inline syntax continue using the selected first-letter or title-case behavior.

## Safety and compatibility

- The rule remains deliberately conservative: when text may be case-sensitive, TPS Linter skips capitalization for the entire heading instead of trying to rewrite only selected fragments.
- Case protection uses bounded linear checks and is covered at the existing 32,000-character per-line limit. Pathological incomplete domain- and angle-like input cannot create an unbounded save-time scan.
- Existing frontmatter, protected-block, note-local control, second-pass idempotence, output-limit, active-editor, exact-file, editor-revision, lifecycle, exclusion, current-settings, and atomic `Vault.process` guards remain unchanged.
- No setting, default, schema field, migration, stable rule ID, command, exclusion, filename rule, or minimum Obsidian version changes. Minimum supported Obsidian remains `1.10.0`.

- Focused heading case-safety tests: `65/65` passed across both capitalization modes, including punctuation-adjacent and Unicode tags, links and embeds, URL/URI/domain/path forms, escaped syntax, counters, level-only changes, idempotence, and bounded maximum-line cases.
- Complete unit/property suite: `248/248` passed.
- Structural/settings contracts: `16/16` passed.
- Historical differential: `10,003/10,003` cases preserved exact controls and non-capitalization Markdown results against the pinned `0.5.5` baseline.
- TypeScript, final build, test-runtime deployment, and reload: passed. The required separate production-mode build reported `[runtime-deploy] target=test ... unchanged` because the test runtime already matched the final artifacts byte-for-byte; the Hot Reload command was run in Obsidian afterward.
- Live test-vault QA: manual Clean preserved tags, wikilinks, Markdown links, URLs, punctuation-adjacent tags, emoji-leading tags, HTML entities, and internationalized domain/path text byte-for-byte while capitalizing only plain controls and independently normalizing heading levels. ## Known limitations

- Protection is intentionally whole-heading and conservative. Ordinary prose containing path-like separators, URI-like colons, domain-like dotted tokens, or Markdown control characters can therefore retain its existing case.
- Heading-level normalization can still change outline and section structure by changing the number of hashes; disable that independent rule where structural stability is more important.
