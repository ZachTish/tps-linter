# TPS Linter 0.5.7

TPS Linter `0.5.7` is a backward-compatible performance release. An unequal editor/file comparison now avoids normalizing both complete strings when neither buffer contains a representation that normalization could change.

## Changes

- Keeps the existing exact-string fast path.
- Detects the only released representation differences—one leading BOM or any CR/CRLF line ending—before normalizing.
- Unequal editor/file buffers with neither a leading BOM nor any carriage return now return the same released mismatch result without running representation normalization.
- When one or both buffers need normalization, normalizes only those buffers and retains the released comparison result.
- Adds one small pure helper and no state, cache, retry, fallback route, monkeypatch, polling, or unsupported Obsidian behavior.

## Objective before/after evidence

- Actual exact `0.5.6` and candidate modules produced zero mismatches across 100,000 seeded generated editor/file pairs containing ordinary text, LF, CR, CRLF, leading and embedded BOMs, Unicode, exact equality, representation-only differences, and real content differences.
- An independent adversarial review then found zero mismatches across 8,225,424 exhaustive pairs and 300,000 additional seeded random pairs, including NUL, Unicode separators, emoji, and unpaired surrogate halves.
- Of those pairs, 10,995 unequal ordinary-LF cases can now skip representation normalization deterministically.
- On two unequal 1,500,001-character LF buffers, 20 comparisons measured 21.842 ms median in exact `0.5.6` and 2.575 ms in the candidate across 21 interleaved rounds, an 88.2% reduction.
- On a representation-equivalent 1,000,001-character LF buffer and BOM+CRLF buffer, ten comparisons measured 255.237 ms and 253.517 ms respectively. The compatibility path remained within ordinary run variance.
- The deterministic acceptance gate is zero normalization calls for unequal buffers whose eligibility helper is false; elapsed time is supporting seam-level evidence rather than a whole-plugin claim.
- The production bundle grows by 114 bytes for the explicit eligibility check.

## Validation

- Exact `0.5.6` was pinned at commit `c93b704e928cd7fc5e6031ef0fd606b0e582e11c`.
- The untouched baseline passed all 141 unit/property tests, all 13 structural/settings contracts, TypeScript, and its production build with runtime deployment suppressed.
- The focused regression failed before implementation because the released module had no normalization-eligibility boundary.
- The candidate focused scheduler suite passes 9/9, including the new ordinary-LF gate and the existing exhaustive equivalence test.
- The final versioned release tree passes 142 unit/property tests, 13 structural/settings contracts, TypeScript, and the mandatory separate production-mode build.
- In Obsidian 1.12.7, exact `0.5.6` and the candidate both reported `Filename is already clean. Markdown would change: reorder 4 frontmatter fields.` for the same read-only Check command against `Examples/TPS Base Filter Lab/00 - Start Here.md`.
- The inspected note and runtime-owned `data.json` remained byte-identical across deployment, reload, and UI verification. Production was not accessed.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No command, setting, default, cleanup rule, data field, output contract, work limit, compatibility behavior, or plugin API is removed or changed.
- No settings or data migration is required.
- Exact editor/file equality was already constant-time and remains unchanged.
- The measured gain applies when an editor and persisted note are unequal and both already use LF without a leading BOM. Leading-BOM, CRLF, and lone-CR buffers retain exact `0.5.6` representation-normalization semantics.
