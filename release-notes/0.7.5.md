# TPS Linter 0.7.5

TPS Linter `0.7.5` adds an independent, fail-closed frontmatter-envelope invariant. If a note already has closed top-of-note frontmatter, no cleanup result can be returned or written unless its exact opener and closer remain present.

## User-visible changes

- Existing `---` and `...` frontmatter closers are protected by a final pre-write verification in addition to the line scanner and sorter safeguards.
- If any current or future rule proposes changing or removing an existing delimiter, TPS Linter rejects the complete note mutation and reports a safety block instead of writing partial cleanup.
- Automatic triggers, commands, settings, rule defaults, schema `7`, exclusions, filename ownership, and settings sync remain unchanged.

## Investigation and safety

- The released `0.7.4` cleaner had no reproduced delimiter-deletion path: frontmatter lines were protected, sorting spliced the original closer and body back into the note, and the isolated test vault contained no unterminated frontmatter notes at audit time.
- Multiple TPS plugins can legitimately perform guarded frontmatter writes when a note opens. The new invariant is intentionally local to TPS Linter: it prevents this plugin from ever committing delimiter loss without claiming another writer caused the intermittent report.
- The verifier recognizes byte-zero and BOM-prefixed top-of-note frontmatter, exact `---` or `...` closers, supported line endings, and delimiter-line whitespace. It does not invent or repair a closer for an already-unclosed input.
- The existing fresh-read, active-editor equivalence, exact-file identity, exclusion, lifecycle, second-pass idempotence, output-size, and atomic `Vault.process` guards remain in force.

## Validation

- Complete unit/property suite, including the focused frontmatter-envelope, spacing, sorting, line-ending, BOM, and malformed-input coverage: 270/270 passed.
- Structural/settings contracts: 18/18 passed.
- Historical non-capitalization differential: 10,003/10,003 cases matched the exact frozen `0.5.5` source at commit `fd2bfbb968e0615c27256725f7bed06aaf0a2162`.
- The no-frontmatter fast path was retained so ordinary large Markdown bodies are not duplicated or split solely for the final envelope check; the suite's performance budgets pass.
- The full declared suite and a separate final `npm run build` passed TypeScript and production bundling. The stable build deployed to the isolated Obsidian Plugin Test Vault; source and runtime artifacts are byte-identical, and the active Obsidian window was verified as `Obsidian Plugin Test Vault` after deployment.
- Production was not accessed, deployed, or reloaded.

## Known limitations

- The verifier prevents TPS Linter from damaging an existing closed envelope; it cannot identify which separate plugin or sync client changed a note before TPS Linter read it.
- An input that is already missing its closer remains unchanged rather than being guessed at or automatically repaired.
