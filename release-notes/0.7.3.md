# TPS Linter 0.7.3

TPS Linter `0.7.3` fixes list-gap cleanup for TPS record lines that contain complete same-line HTML comments. With **Remove blank lines between list items** enabled, the plugin can now recognize the compatible list markers around that safe comment form and remove the intervening blank separator.

## User-visible changes

- Compatible bullet, ordered, and checklist items remain eligible for list-gap cleanup when their text contains one or more HTML comments that open and close on the same physical line.
- TPS inline fields, wiki links, Markdown links, inline math, list markers, HTML comments, line endings, and all other item bytes remain unchanged. Only the eligible ASCII space/tab blank separator is removed.
- Manual Clean and lint on save continue to report the existing **blank line between list items** action and count.
- The existing setting, stable note-local rule ID `list-item-blank-lines`, default-off behavior, and same-remote-vault settings-sync behavior remain unchanged.

## Safety and compatibility

- This is a narrow exception for complete same-line HTML comments. Inline code, Obsidian comments, Templater, generic/raw/delimited HTML, multiline or unclosed comments, mixed protected families, and scanner ambiguity remain ineligible.
- Existing same-indentation, blockquote-path, marker-family, ordered-list proof, and plain-versus-checklist requirements remain unchanged. Nested transitions, continuation paragraphs, thematic-break-like markers, and mixed list types are still preserved.
- Item text is never rewritten by this rule. Frontmatter, fences, math blocks, indented code, disabled ranges, note-local controls, work budgets, output limits, second-pass verification, active-editor guards, and atomic `Vault.process` mutation remain fail-closed.
- Settings schema remains `7`; no setting key, default, command, migration, exclusion, filename behavior, or minimum Obsidian requirement changes. Minimum supported Obsidian remains `1.10.0`.

## Known limitations

- **Remove extra blank lines** still collapses a run to one blank line; it does not remove a single structural separator. **Remove blank lines between list items** owns removal of the final eligible separator.
- Only ASCII space/tab blank-only separators are eligible. Unicode whitespace and other invisible content remain unchanged.
- Complete same-line HTML comments are the sole protected-line exception. Other protected or structurally ambiguous item boundaries remain unchanged rather than being guessed at.
- Removing the final separator changes an eligible CommonMark list from loose to tight, so the rule remains opt-in and default-off.
