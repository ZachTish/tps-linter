# TPS Linter 0.5.5

TPS Linter `0.5.5` is a backward-compatible performance release. It avoids loading the YAML parser for ordinary note frontmatter that cannot contain a TPS Linter control, while preserving every released command, rule, setting, safety guard, and note-local control form.

## Changes

- After the existing frontmatter character and line limits, the control reader performs a bounded text check for either exact TPS control-key text or a backslash.
- Frontmatter with neither signal returns the same no-controls result without constructing a YAML document.
- Any literal control-key candidate still uses the complete released YAML validation path.
- Any backslash conservatively retains full parsing so escaped quoted keys such as `"\u0074ps-linter"` remain supported.
- The implementation adds no persistent cache, settings/data state, fallback route, retry, monkeypatch, polling, or unsupported Obsidian API.

## Objective before/after evidence

- On exact released `0.5.4`, a deterministic 1,000-field frontmatter document without TPS controls measured 5.499 ms median and 5.956 ms p95 across 300 calls after warmup.
- The final `0.5.5` implementation measured 0.059 ms median and 0.083 ms p95 on the identical fixture and process, a 98.9% median reduction at this parser seam.
- Total measured time fell from 1,649.24 ms to 19.68 ms across the 300 calls.
- Control-bearing or backslash-bearing frontmatter intentionally keeps the released parser cost because preserving exact and escaped controls takes priority over speculative parsing shortcuts.
- These measurements describe the isolated no-control frontmatter parser seam, not a universal whole-plugin speedup.

## Validation

- The untouched exact `0.5.4` baseline passed its complete 139-test unit/property suite, 12 structural/settings contracts, TypeScript, and production bundle.
- Before the source change, the focused optimization contract failed because no pre-parser exit existed.
- The final versioned `npm test` passed:
  - 140 unit/property tests.
  - 12 structural/settings contracts.
  - TypeScript and the production bundle.
- Focused coverage includes:
  - ordinary valid frontmatter and malformed unrelated YAML;
  - exact, quoted, explicit, flow-map, uniformly indented, and escaped control keys;
  - candidate malformed YAML, unknown or duplicate controls, aliases, anchors, tags, and merge keys;
  - frontmatter character and physical-line safety limits before the fast path;
  - conservative parsing for unrelated backslashes.
- A deterministic 25,007-case differential corpus produced identical results between the frozen released parser and the optimized parser across valid, malformed, duplicate, anchored, tagged, unterminated, BOM, CRLF, literal, escaped, nested, and unrelated-backslash cases.
- A mandatory separate `npm run build` passed and confirmed that final source artifacts deployed to the isolated test runtime.
- Obsidian 1.12.7 was reloaded in the isolated test vault and the plugin commands remained registered without invoking a cleanup.
- Test-runtime `data.json` remained unchanged at SHA-256 `0cad907fa12c9c5859b7b4b3df05d8dcb0d0f071b2a195edfb4d02a744679682`.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No command, setting, default, cleanup rule, data field, output contract, work limit, or plugin API is removed or changed.
- No settings or data migration is required.
- Candidate and escaped controls still incur full YAML parsing by design.
- Existing conservative Markdown/YAML limits and documented unsupported syntax remain unchanged.
