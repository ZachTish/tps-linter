# TPS Linter 0.7.2

TPS Linter `0.7.2` is a settings-reliability patch. It applies settings downloaded by Obsidian Sync without a plugin reload and prevents local settings writes from restoring stale choices over newer synchronized data.

## User-visible changes

- When Obsidian downloads TPS Linter's `data.json`, the plugin now uses the supported `onExternalSettingsChange()` callback to normalize and apply the settings immediately.
- An open TPS Linter settings page refreshes in place and reports that an external update arrived. The selected settings destination remains transient and unchanged.
- **Files & safety → Settings sync** explains that native settings sync connects devices attached to the same remote vault. Separate vaults and separate remote vaults remain independent.
- Copy for the default-off body-spacing and list-gap rules now explains that a choice can be enabled locally or downloaded through same-remote-vault settings sync.

## Persistence and safety

- Local writes are serialized and reread the latest plugin data before saving. Only locally changed known fields are merged, so compatible unknown fields and unrelated settings from another device survive.
- Rapid edits, including an old-new-old sequence while a save is active, preserve the final local intent.
- A local save completing during an external read advances a revision token. The stale external snapshot is discarded and reread instead of regressing the in-memory persistence baseline.
- Local edits made before or during an external read remain locally owned. A failed local write does not let a later downloaded snapshot silently replace that dirty intent.
- A genuine first save creates a complete normalized settings record. If an established `data.json` becomes temporarily unavailable, TPS Linter fails closed rather than writing a partial record that would reset other choices.
- Missing, non-object, malformed-schema, and future-schema external payloads are ignored without writeback. External application never calls `saveData()`, lints a note, scans the vault, or changes note content.
- The settings schema remains `7`; every setting key, default, command, rule ID, exclusion, and minimum Obsidian requirement remains unchanged. Minimum supported Obsidian is `1.10.0`; the external-settings API has been available since Obsidian `1.5.7`.

## Known limitations

- Obsidian Sync settings are vault-scoped. This release does not create an account-wide TPS profile or automatically bridge independent vaults, the isolated test vault, and production.
- Obsidian Sync category selections are device-local. **Community plugins** and their settings must be enabled on every participating device for the same remote vault; changing those selections may require restarting or force-quitting Obsidian.
- If two devices edit the same setting concurrently, the last synchronized value can still win according to Obsidian Sync's conflict behavior. TPS Linter prevents its own stale whole-object writeback but does not replace Obsidian's conflict resolution.
