# TPS Linter 0.5.1

TPS Linter `0.5.1` is a backward-compatible efficiency release. It removes repeated work from the existing active-note save path and frontmatter sort without changing commands, settings, defaults, cleanup output, mutation guards, or persisted data.

## Changes

- Exact editor/file matches now return before allocating normalized copies. The existing BOM and LF/CRLF/CR equivalence fallback remains byte-for-byte compatible.
- Save linting reuses its verified preflight cleanup only when the `Vault.process` callback receives the exact same bytes and a fresh snapshot of every cleanup option has the same fingerprint. Concurrent file or setting changes still run a fresh cleanup inside the atomic callback.
- Frontmatter sorting folds each key and resolves its configured priority once per field instead of repeating string normalization during sort comparisons.

## Performance evidence

- Exhaustive fragment-pair coverage proves the editor/file fast path returns the same result as the former normalization-only implementation.
- A local 1.7-million-character exact-match benchmark reduced 40 comparisons from roughly 44 ms median to effectively constant-time string identity checks; the representation-normalization fallback remained within ordinary run variance.
- A representative 35,000-line dirty note took roughly 52 ms for one cleanup and 111 ms for the former two-cleanup save path. The second cleanup is now skipped only under the exact revision-and-options guard.
- Frontmatter key normalization is now proportional to field count rather than comparator count.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings or data migration is required.
- Existing conservative Markdown/YAML limits and documented unsupported syntax remain unchanged.
- This release optimizes only proven repeated work; it does not add background scans, caches, fallbacks, or new state.
