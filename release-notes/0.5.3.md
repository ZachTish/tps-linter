# TPS Linter 0.5.3

TPS Linter `0.5.3` is a backward-compatible reliability release. It keeps manual inspection, atomic Markdown cleanup, and filename cleanup attached to the exact selected vault file even if another note is deleted and recreated at the same path.

## Changes

- Manual Check/Clean now requires the selected Markdown `TFile` to remain the exact object indexed by the vault.
- Identity is verified before and after the inspection read, inside the atomic `Vault.process` callback, after processing, and after the final filename read.
- A deleted, non-Markdown, or different same-path file is rejected before it can inherit content parsing, cleanup, filename planning, or rename work.
- A supported rename of the same `TFile` remains eligible because its updated path still resolves to the same object.
- Path exclusions remain a distinct `path-excluded` result; identity loss reports an `invalid-plan` safety result.
- The implementation uses only supported `Vault.getFileByPath`, `Vault.process`, and `FileManager.renameFile` behavior. It adds no retry, path reacquisition, adapter mutation, cache, polling, fallback route, or monkeypatch.

## Objective reliability evidence

- On released `0.5.2`, the new orchestration contract failed because manual cleanup accepted any Markdown `TFile` found at the original path.
- The final identity helper accepts the original indexed Markdown object and rejects:
  - deletion;
  - a different object with the same path and stat values;
  - a non-Markdown object.
- The orchestration contract proves the two inspection checks bracket the asynchronous read, the atomic callback returns the current bytes with `invalid-plan` on identity loss, and post-process/final-read checks occur before parsing, planning, or rename.
- The wrong-file mutation opportunity changes from potentially one content/filename action to zero. Ordinary output is unchanged; no timing benchmark is meaningful for this constant-time safety check on an explicit manual action.

## Validation

- The released `0.5.2` baseline passed 135 unit/property tests and 11 structural/settings contracts before implementation.
- The final versioned `npm test` passed:
  - 136 unit/property tests.
  - 12 structural/settings contracts.
  - TypeScript and the production bundle.
- Two independent read-only reviews found no missing externally controllable asynchronous boundary or normal-feature regression.
- A separate final `npm run build` passed and deployed byte-identical artifacts only to `.obsidian/plugins/tps-linter` in the isolated test vault.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. In a synthetic Inbox note, **TPS Linter: Clean current note** cleared one whitespace-only line, capitalized one heading, and adjusted one heading level. A second invocation reported both the filename and Markdown already clean. The note was then moved to `_archive`.
- Test-runtime `data.json` remained unchanged at SHA-256 `0cad907fa12c9c5859b7b4b3df05d8dcb0d0f071b2a195edfb4d02a744679682`.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No command, setting, default, cleanup rule, data field, or plugin API is removed or changed.
- No settings or data migration is required.
- Existing conservative Markdown/YAML limits and documented unsupported syntax remain unchanged.
- Races internal to Obsidian's supported atomic process/rename implementations remain owned by Obsidian; TPS Linter does not add unsupported adapter checks or retries around them.
